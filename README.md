# مركز المستقبل — Future Center

تنفيذ المراحل الأولى إلى الخامسة بـMERN + TypeScript. المرجع المعتمد: `Future-Center-UX-Pack-V2`. ملفات التصميم الأصلية محفوظة كما هي.

## التشغيل المحلي

يتطلب Node.js 22.12 أو أحدث، وMongoDB تدعم transactions عبر replica set.

```sh
npm ci
npm run dev
```

- الموقع: http://127.0.0.1:5176
- API: http://127.0.0.1:5001/api/health
- MongoDB الخاصة بالمشروع: `127.0.0.1:27027`، قاعدة `future_center` وreplica set باسم `future-center`.

أداة التشغيل على Windows تستخدم MongoDB المثبتة على الجهاز، وتضع البيانات في `.local/mongo` وتربط الخدمة بـlocalhost فقط. لا تعدّل خدمة MongoDB أخرى. يُنشأ `.env` مرة واحدة بقيم عشوائية مستقلة للأسرار؛ لا يُعرض محتواه في السجل ولا يُضاف إلى Git. لإعداد مختلف، انسخ `.env.example` وعدّل `MONGODB_URI` والأسرار قبل التشغيل. عند وجود MongoDB في مكان آخر، عيّن `MONGOD_PATH` أو استخدم replica set خارجية عبر `MONGODB_URI`.

المعاينة المحلية تعمل حاليًا، ولم يُنشر الموقع على استضافة خارجية. لإيقاف التطبيق اضغط Ctrl+C في جلسة التشغيل. قاعدة المشروع المحلية تستمر مستقلة لإعادة التشغيل دون فقد البيانات؛ PID الخاص بها موجود في `.local/mongo.pid`.

## ما تم تنفيذه

### المرحلة الأولى

واجهة React + Vite + TypeScript، وTailwind CSS ونظام التصميم الموافق لـV2. سيرفر Express، وقاعدة MongoDB/Mongoose، والتحقق المشترك بـZod، وسكربتات التشغيل والبناء والاختبار. الهيكل `client / server / shared`.

### المرحلة الثانية

الرئيسية بأقسامها الخمسة، عن المركز، قائمة البرامج وتفاصيل البرنامج، المقالات وصفحة المقال، التواصل، سياسة المواعيد والخصوصية، صفحة 404، قائمة الهاتف، وزر واتساب. الصور والخطوط نفسها من V2 ومحفوظة محليًا. جميع الروابط الأساسية تعمل مع تصميم مستقل للموبايل والتابلت والديسكتوب.

أضيفت بيانات المركز التي زوّد بها المالك: `01041504201` و`01041507409`، والعنوان «كفر الزيات، شارع الجيش عند توكيل أورنج». الرقم الأول مستخدم لواتساب مبدئيًا. ساعات العمل والأسعار ما زالت بيانات تجريبية مع توضيح ذلك في واجهة الحجز والبرامج. لا توجد بيانات طبيبة أو مؤهلات مختلقة.

### المرحلة الثالثة

- حجز ضيف بالخدمة واليوم والوقت والاسم والهاتف وواتساب اختياري مختلف، وموافقة التواصل.
- أوقات فعلية من السيرفر، بتوقيت Africa/Cairo. حجب الأيام المغلقة والاستراحات والفترات المحظورة والأوقات السابقة، مع نافذة حجز 90 يومًا وحد أدنى 15 دقيقة قبل بداية الموعد.
- حجز ذري باستخدام MongoDB transactions وفهرس unique على خلايا الوقت كل 5 دقائق؛ يمنع تداخل جلسة 45 دقيقة مع جلسة تبدأ أثناءها، وليس تكرار وقت البداية فقط.
- منع تكرار الطلب عند إعادة المحاولة بواسطة `Idempotency-Key`. يحتفظ النموذج بالمدخلات ويحدّث الأوقات عند التعارض.
- حالة «بانتظار الموافقة» بعد نجاح الحفظ، ثم تأكيد أو رفض أو إلغاء. مهلة المراجعة الافتراضية 24 ساعة، أو حتى بداية الزيارة إن كانت أقرب، قابلة للضبط في `PENDING_HOLD_HOURS`. هذه سياسة تشغيل مقترحة لحين اعتماد المركز.
- رابط متابعة خاص بمفتاح 256-bit لا يظهر في query string أو رسائل واتساب. يرجع API بيانات اتصال مقنعة؛ حامل الرابط يستطيع طلب التغيير والإلغاء، لذلك لا يُشارك الرابط.
- طلب إعادة جدولة يحافظ على الحجز الأصلي؛ لا يُحجز البديل حتى اعتماد الإدارة، ثم يُنقل الحجز ذريًا مع التحقق من التعارض مرة أخرى.
- النتيجة «مكتمل/لم يحضر» تتطلب قرار الإدارة بعد انتهاء وقت الزيارة. مرور الوقت وحده لا يثبت الحضور.
- طلب برنامج منفصل يُحفظ في قاعدة البيانات بحالة `new`، ثم يتيح فتح واتساب برقم الطلب. لا يفعّل اشتراكًا ولا ينفذ دفعًا أو يرسل رسالة تلقائيًا.

### المرحلة الرابعة — الحساب الشخصي

- `/register` لإنشاء حساب برقم الهاتف وكلمة المرور، و`/login` للدخول. الحجز كضيف يظل متاحًا.
- كلمات المرور مشتقة بـscrypt، والجلسات عشوائية ومحفوظة كـhash في MongoDB داخل cookies من نوع HttpOnly وSameSite=Lax. في الإنتاج تستخدم Secure واسم `__Host-fc_session`، مع التحقق من مصدر الطلبات المعدلة للبيانات.
- جلسة المريض 24 ساعة، أو 30 يومًا مع «تذكّرني». جلسة المدير 8 ساعات. الخروج يبطل الجلسة في السيرفر؛ تغيير كلمة المرور واستعادتها يبطلان الجلسات الأخرى، مع مراجعة إصدار بيانات الدخول في كل طلب.
- رمز استعادة عشوائي يظهر مرة واحدة عند التسجيل؛ `/recover` يستبدل كلمة المرور بالرمز، ويصدر رمزًا جديدًا ويبطل القديم. لا توجد خدمة SMS/OTP موصولة أو ادعاء بالتحقق من ملكية الرقم.
- `/account` يعرض المواعيد القادمة وسجل الزيارات وتحديثاتها، وطلبات التغيير والإلغاء، والبرامج والاشتراكات وعدد الجلسات المتبقية. يمكن تعديل الاسم وكلمة المرور.
- الحجوزات والطلبات الجديدة أثناء الدخول ترتبط بالحساب. حجوزات الضيف القديمة لا تظهر بتطابق الهاتف؛ إضافتها تتطلب رابط المتابعة الخاص. لا يمكن نقل حجز مرتبط بحساب آخر.
- الحساب لا يتضمن ملفات طبية أو تشخيصات أو قياسات صحية؛ هذه ليست ضمن النطاق المنفذ.

### المرحلة الخامسة — لوحة إدارة فعلية

- `/admin`: إحصاءات فعلية، بحث بالاسم والهاتف والمرجع، تصفية اليوم والخدمة والحالة وطلبات التغيير، وقائمة بصفحات وتفاصيل الطلب وسجله.
- الموافقة والرفض بسبب، الإلغاء، اعتماد إعادة الجدولة أو رفض اقتراح التغيير مع إبقاء الأصل، مكتمل/لم يحضر بعد نهاية الزيارة، وإضافة طلب موعد يدوي. واتساب يفتح للعميل برسالة جاهزة ولا يرسل تلقائيًا.
- `/admin/programs`: إضافة وتعديل الخدمات والبرامج والأسعار والمدة والجلسات والمميزات. إخفاء برنامج يمنع طلبات جديدة دون حذف حجوزاته وسجلاته السابقة. الأسعار القديمة محفوظة كلقطة في الحجز أو الاشتراك.
- `/admin/patients`: طلبات البرامج وتحديث حالتها والتواصل مع العميل، قائمة حسابات المرضى، وإنشاء وتعديل اشتراك لضيف أو ربطه بحساب اختارته الإدارة بعد التحقق من صاحبه. توثيق القيمة المتفق عليها، البداية والنهاية والحالة وإجمالي الجلسات والمستخدم منها. لا يثبت سدادًا ولا يخصم مالًا.
- `/admin/articles`: إضافة وتعديل المقالات ونشرها أو حفظها كمسودة؛ تظهر المنشورات فقط في الموقع. الصور هي صور الهوية المحلية المعتمدة، والمحتوى نص عادي.
- `/admin/schedule`: ساعات أيام الأسبوع، استراحات متعددة، وحظر فترات بالتاريخ. الحظر لا يلغي موعدًا قائمًا بصمت.
- `/admin/settings`: بيانات المركز والتواصل وواتساب وتنبيه الأسعار التجريبية، مع سجل التعديلات الإدارية.
- الصفحات محمية بصلاحية المدير في السيرفر. التسجيل العام لا يمنح صلاحيات إدارة، ومفتاح API الإداري لا يُستخدم بالواجهة. تحميل شاشات الحجز والحساب والإدارة عند الحاجة.

## أول دخول للإدارة

```sh
npm run admin:create
```

ينشئ الأمر مديرًا محليًا مرة واحدة فقط على رقم المركز `01041504201`، بكلمة مرور ورمز استعادة عشوائيين. بيانات الدخول الأولية في `.local/admin-access.txt` داخل المشروع، وهو مجلد مستبعد من Git. افتح `/login` ثم `/admin`، ويمكن تغيير كلمة المرور من `/account`. بعد تغييرها، كلمة المرور القديمة في الملف لا تعود صالحة. إعادة تنفيذ الأمر لا تغير حسابًا قائمًا ولا ترقي حساب مريض. لا تنشر `.local` أو `.env` أو ملفات تقارير اختبار فاشل.

استعادة حساب فقد رمزه تتم بعد تحقق المركز من هوية صاحبه. توجد أداة تشغيل محلية لتعيين كلمة مرور جديدة وإلغاء جلساته؛ تمرر كلمة المرور عبر stdin، ولا تضعها في معاملات الأمر أو سجلاته:

```sh
npm run account:reset -- --phone=01012345678
```

الأداة تطلب كلمة المرور بشكل مخفي في الطرفية، أو تقرأ stdin حتى نهايته عند إعادة التوجيه، وتكتب رمز الاستعادة الجديد في ملف خاص داخل `.local/recovery-*.txt`. لا ترسل كلمة المرور أو الرمز عبر محادثة عامة. التحقق من هوية صاحب الرقم إجراء تشغيلي على المركز، وليس تحققًا آليًا في هذا الإصدار.

## إدارة التوافر والطلبات محليًا

لوحة الإدارة المرئية تعمل من `/admin` بجلسة مدير محمية. يظل `ADMIN_API_KEY` الموجود في `.env` متاحًا للأداة المحلية وطلبات الإدارة من السيرفر فقط، ولا يدخل كود المتصفح. الأوامر المحلية متاحة أيضًا:

```sh
npm run manage -- list
npm run manage -- approve FC-REFERENCE
npm run manage -- reject FC-REFERENCE "يرجى اختيار وقت آخر"
npm run manage -- reschedule FC-REFERENCE 2026-11-15 11:00
npm run manage -- cancel FC-REFERENCE
npm run manage -- complete FC-REFERENCE
npm run manage -- no_show FC-REFERENCE
npm run manage -- schedule
npm run manage -- interests
```

لتحرير جدول العمل، صدّر JSON مباشرة دون ترويسة npm، وعدّل الملف، ثم أرسله:

```sh
node --env-file=.env scripts/manage.mjs schedule > schedule.local.json
npm run manage -- schedule:set schedule.local.json
```

يتضمن الجدول `hours` لأيام ISO من 1=الاثنين إلى 7=الأحد، و`blocks` لفترات محددة بالتاريخ. كل يوم يتضمن `open/start/end/breaks`. يمكن وضع `demoSchedule: false` عند اعتماد ساعات العمل الفعلية. حظر فترة جديدة يمنع الطلبات الجديدة ولا يلغي حجوزات سابقة بصمت؛ عالج الموعد القائم صراحة من أداة الإدارة. لا تستخدم المفتاح الإداري في المتصفح أو أي متغير يبدأ بـ`VITE_`.

## API الأساسي

- `GET /api/catalog` — بيانات المركز والبرامج والمقالات.
- `GET /api/availability?serviceId=nutrition&date=YYYY-MM-DD` — أوقات اليوم للخدمة.
- `POST /api/appointments` — طلب موعد؛ يتطلب `Idempotency-Key` من نوع UUID.
- `GET /api/appointments/track` — متابعة بمفتاح `Authorization: Bearer <private-token>`.
- `POST /api/appointments/cancel` — إلغاء بواسطة المفتاح الخاص.
- `POST /api/appointments/reschedule` — إرسال وقت مقترح بواسطة المفتاح الخاص.
- `POST /api/interests` — حفظ طلب برنامج.
- `GET /api/admin/appointments` و`POST /api/admin/appointments/:reference/decision`.
- `GET/PUT /api/admin/schedule` — ساعات العمل والفترات المحظورة.
- `GET /api/admin/interests` — طلبات البرامج.

النماذج تتحقق من المدخلات، وتدعم الأرقام العربية وتطبيع أرقام الهاتف. الطلبات الإدارية تحتاج المفتاح، والبيانات الحساسة لا تُسجّل في سجلات HTTP. توجد حدود لمعدل الطلبات وحجمها ورسائل أخطاء مناسبة. لا يوجد دفع إلكتروني أو رسائل واتساب آلية. تسجيل الدخول وحساب المريض ولوحة الإدارة مرتبطة بقاعدة البيانات.

## الفحص والبناء

```sh
npm run typecheck
npm test
npm run test:e2e
npm run build
node scripts/visual-check.mjs
```

اختبارات السيرفر تستخدم قاعدة منفصلة مؤقتة باسم `future_center_test_*` على نفس replica set، وتزيلها بعد الانتهاء. تختبر التزامن والتداخل وإعادة المحاولة والمهلة والإلغاء وإعادة الجدولة والتوافر والتحقق وحماية الإدارة، والحسابات والجلسات واستعادة كلمة المرور وعزل الملكية والاشتراكات والأسعار والنشر.

اختبارات المتصفح تحتاج `npm run dev` يعمل مسبقًا، وحساب المدير المحلي الناتج عن `npm run admin:create`. تعمل على الحجز والمحتوى والمقاسات، ولا ترسل أي رسالة واتساب. `artifacts/` يحتوي صور الموقع الفعلي وتقرير الخطوط والصور والتمدد الأفقي. اختبارات المتصفح تنشئ بيانات اصطناعية بأسماء واضحة. إعداد البداية والنهاية يزيل هذه السجلات المحددة فقط من قاعدة المعاينة `future_center` باستخدام `scripts/clean-browser-fixtures.mjs`. أداة التحقق البصري تستخدم Chromium المتوفر في البيئة؛ يمكن تثبيت المتصفح عبر `npx playwright install chromium` عند الحاجة.

للتشغيل بعد البناء اضبط `NODE_ENV=production` و`PUBLIC_ORIGIN/CLIENT_ORIGIN` و`MONGODB_URI` والأسرار الفعلية ثم `npm start`. Express يقدم ملفات `client/dist` في هذا الوضع. النشر الخارجي لم يُنفذ. يجب استخدام HTTPS وأصل الموقع الفعلي في إعدادات الإنتاج كي تعمل جلسات Secure بشكل صحيح.

## البنية والصيانة

التفاصيل في [دليل البنية](ARCHITECTURE.md). الواجهة مقسمة حسب الوظيفة في `client/src/features`، وتجميع التطبيق في `client/src/app`. السيرفر يفصل المسارات وmiddleware والخدمات والموديلات وتشكيل الاستجابات. العقود المشتركة في `shared/src`، وملفات الهوية والتجاوب في `client/src/styles`.

```sh
npm run format
npm run format:check
```

البناء ينظف مجلدات `dist` أولًا. صور V2 وخطوطه ومصادر التصميم الأصلية محفوظة، ولم تدخل ضمن إعادة تنظيم المصدر.

الأسعار والجلسات الافتراضية من مرجع التصميم وليست أسعارًا معتمدة. البيانات الأولية تُضاف عند إنشاء قاعدة البيانات فقط، ولا تستبدل تعديلات لاحقة. الصورة التي تظهر فيها مختصة تعبيرية للهوية، وليست تعريفًا بالطبيبة الحقيقية.

## الدخول السريع المحلي

صفحة `/login` في وضع التطوير المحلي تعرض زرّي Admin وUser (المريض). زر Admin يفتح حساب الإدارة الموجود، وزر User ينشئ حساب تجربة مستقلًا مرة واحدة. لا تُضاف أدوار جديدة. الاختصار محمي في السيرفر بوضع development وربط السيرفر بعنوان loopback واتصال loopback؛ يرجع 404 في الإنتاج، ولا يظهر في واجهة البناء النهائي.
